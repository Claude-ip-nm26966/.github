<p>机房段吃过亏的人再买住宅 IP，最容易犯的错是只算线路单价：一条多少钱、一个月多少钱，算完觉得比原来贵两倍就犹豫。其实线路费在总成本里往往不到一半，真正吃钱的是迁移时重建环境的工时、老号与新号混跑带来的连带折损，以及为省单价反复换供应商的隐性开销。这篇把四笔账分开算，并给出分线方案在什么号量下才划算，价格给区间，仅供参考。</p>
<h2>一、按号龄把账拆成两套</h2>
<p>老号和新号的成本结构完全不同，混在一起算会得出错误结论。老号的成本重心在「保住」，新号的成本重心在「试错」。</p>
<h3>老号：贵在折损，不在出口</h3>
<p>一个跑过几个月、有对话历史和订阅状态的号，重建成本包括重新注册、重新积累使用记录、重新验证支付方式，折算下来通常是月线路费的好几倍。所以老号该配稳定出口，贵一点也值得，账要按「一条线能保住几个老号」来算。</p>
<h3>新号：贵在试错，出口可以轻一点</h3>
<p>新号还没有沉没成本，被拦了可以换。这类号适合走批量、走成本更低的方案，把省下来的钱留给老号。但前提是新号的环境必须独立，一旦和老号共用出口，试错的代价就直接转移到老号身上。</p>
<h2>二、四条成本线逐项拆</h2>
<p>四条线分别是出口占用、环境与设备、迁移重建、连带折损。前两条可预算，后两条浮动大，也最容易被漏算。</p>

<h3>出口占用为什么老号更贵</h3>
<p>老号要的是「地址不变」，只能用静态独享，无法共享；新号可以接受按量池，用完就换。这个差别直接决定了单价，不是商家定价偏心。</p>
<h3>环境费的隐藏部分：闲置</h3>
<p>开了环境但两周没登录的，算闲置。闲置环境的成本是纯支出，还会拉高备份与巡检的工时。把闲置率控制在 10% 以内，环境费能省两成左右。</p>
<h2>三、迁移成本：从机房段换过来的一次性账</h2>
<p>迁移不是换个代理地址那么简单。机房段换成住宅段，等于把网络身份整体换掉，环境要重配、登录态要重建、验证要重走一遍。</p>
<h3>单号迁移的四步与工时</h3>
<p>核验新出口归属、重建浏览器环境、重新登录并完成可能的验证、观察三天确认稳定。四步下来熟手约半小时，生手一到两小时。五十个号就是二十五到一百小时，这笔账要先算进去再谈单价。</p>
<h3>迁移期要不要停业务</h3>
<p>建议不停，但要分批。一次迁十个号，迁完观察三天再迁下一批。全量一起迁的风险是：新线路如果整体不达标，所有号同时进入观察期，等于业务停摆一周。</p>

<h2>四、什么时候分线反而不划算</h2>
<p>分线是降低风险的手段，但它本身有固定成本。号少的时候，分线摊到每个号上的开销可能超过风险本身的价值。</p>

<h3>五个号以下的现实选择</h3>
<p>这个量级谈分线意义不大，收益被固定成本吃掉。更实际的做法是把老号集中在一到两条独享线上，新号单独走池子，两组之间不共用任何出口，这已经能隔开绝大部分连带风险。</p>
<h3>分组的界线按什么划</h3>
<p>优先按「注册地区」划，其次按「号龄」。同地区的号放一组，出口城市一致，环境不容易错位；老号新号分开，试错不会传染。</p>
<h2>五、压成本的三条实操</h2>
<p>成本能压的地方不多，但压对地方效果明显，且不影响稳定性。</p>
<h3>第一条 回收闲置环境与出口</h3>
<p>每月清一次：三十天未登录的号，环境降级为模板，出口退回或转按量。这一条通常能省下总成本的 15% 到 25%，是投入产出比最高的动作。</p>
<h3>第二条 用按小时口径扛过渡期</h3>
<p>团队交接、临时顶替、短项目，用按小时计费撑过去，别为两周的需求开一年。过渡期结束后再决定是否转包月。</p>
<h3>第三条 单价差三成以内不换供应商</h3>
<p>换供应商的隐性成本约等于半个月人力加一次全量迁移。省下的单价差额通常填不平这个坑，除非差价超过三成且合同周期足够长。</p>
<h2>常见问答</h2>
<h3>机房段换住宅段，成本大概涨多少？</h3>
<p>答：出口单价通常涨两到四倍，但总成本涨幅小得多，因为连带折损会明显下降。经验上，账号折损率从每月一成降到两三个点，抵消掉大半涨价。</p>
<h3>老号新号一定要物理分开吗？</h3>
<p>答：不要求物理隔离，但要求网络身份分开：不同出口、不同环境、不同登录时段。共用一台机器没问题，共用一条出口就是风险串联。</p>
<h3>迁移期出现验证增多，是不是线路不行？</h3>
<p>答：先看是不是迁移节奏的问题。一次性迁太多、或在同一时段集中登录，都会让验证变多。分批迁、错开时段，多数情况会缓解。</p>
<h3>预算很紧，先省哪一块？</h3>
<p>答：省新号的出口，别省老号的。新号被拦可以重开，成本低；老号一旦折损，重建代价高得多。优先级永远是保住存量。</p>
